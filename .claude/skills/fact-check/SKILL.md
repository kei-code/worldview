# WorldView ファクトチェック・スキル

記事を**公開（コミット）する前に必ず通す**検証工程。CLAUDE.md「運用上の絶対ルール」で必須と定めている。

対象は**これから公開する新規記事**。公開済みの過去記事の棚卸しは現時点でスコープ外。

---

## 中核となる原則

**書いた本人は、自分の記事の最悪のチェッカーである。**

自分が書いた文を読み返すとき、記憶が「これは調査で得た数字だ」と告げるため、再検証をスキップする誘因が働く。実際にこの失敗は起きている（下記「過去の失敗事例」参照）。

したがって：

- **検証は必ずサブエージェント（Sonnet）に委譲する**。サブエージェントは記事HTMLしか読めないため、「覚えている」を根拠にできず、すべてを一次資料から確認せざるを得ない。この制約が利点になる。
- **サブエージェントの役割は「検証と報告」まで**。修正方針の決定（記述を直すか、図表を削るか、表現を弱めるか）は編集判断であり、本体エージェントとユーザーが行う。
- 検証は**記事の記述を信用しない**。「記事にこう書いてある」は根拠にならない。必ず一次資料に当たる。

---

## 実行手順

### 1. サブエージェントに委譲する

`Agent` ツール（`subagent_type: "general-purpose"`, `model: "sonnet"`）で起動する。
プロンプトには**記事の絶対パスと、下記「検証項目」の全文**を含めること。サブエージェントは会話の文脈を引き継がないため、指示は自己完結させる。

WebSearch / WebFetch / Read を使わせる。

### 2. 報告を受けて修正方針を決める

サブエージェントの報告を、**重大度で仕分けしてユーザーに提示**する。

- 🔴 **重大**：事実の誤り／根拠のない数値／記事の主張を左右する欠落
- 🟡 **要修正**：数値のズレ、表現の不正確さ、断定の強すぎ
- ✅ **裏付け確認済み**：検証して問題なかった主要記述（何を確認したかを示す）

**判断が要る項目はユーザーに選択肢を出す**（例：出典のない図表を「削除するか／出典のあるデータに差し替えるか」）。勝手に決めない。

### 3. 修正して再検証

修正後、変更箇所についてブラウザで表示確認（コンソールエラー・図表の描画・レスポンシブ）を行う。

## 検証項目

サブエージェントに渡す検査リスト。**すべて記事HTMLのみを入力とし、一次資料に当たって確認する。**

### A. 数値・日付・固有名詞

記事中のすべての数値・日付・組織名・人名・条約名を抽出し、一次資料で確認する。
**記事の記述は信用しない。** 公的機関・学術論文・一次報道を優先し、記事が挙げている情報源そのものも検証対象とする。

### B. 最上級・断定表現（最重要）

**「唯一」「最大」「最初の」「史上初」「すべて」「必ず」「終結した」「完全に」** などを全数抽出し、個別に反例を探す。
**反例が1つでもあれば不合格。**

過去に「史上唯一の独立クルド国家」という記述が誤りだった（アララト共和国など先行例が存在）。この種の表現は書き手が強調のために足しがちで、最も誤りやすい。

### C. チャート・図表の数値（最重要）

グラフ・パーセンテージ表示・進捗バーなど、**数値化されたあらゆる視覚表現**について、出典の原記述に同じ値が存在するかを確認する。Chart.jsのcanvasに限らない——`tone-meter` のような小さなバーも対象。

以下は**不合格**とする：
- 出典が「各種推計」「各種報道」など**特定できない曖昧な表記**
- 定性的な記述（例「陸上埋蔵量を上回る」）から**書き手が逆算・推定して置いた数値**
- 出典があるのは最新値だけで、**過去の推移が補完されている**系列データ
- **測定不能な主観的評価（賛否の強さ・推進度など）をパーセンテージで表現したもの**——出典のある「量」ではなく、書き手の感覚的な強弱判断に過ぎない場合は不合格

数値の裏付けが取れない図表は、記述で代替するか、出典のあるデータに差し替える。

### D. 鮮度（欠落の検出）

**記事の日付は「今日」。したがって「今日までに起きた重大な進展」が漏れていないかを検索する。**

誤りがないことと、記事が最新であることは別問題。過去には、記事の主題そのものに直結する国際会議が記事公開日に開催中だったにもかかわらず、時系列が4か月前で止まっていた例がある。

- 主題に関する直近の動き（会議・判決・法改正・新規発表）を検索する
- 記事のタイムラインの末尾が、今日から見て不自然に古くないか確認する

### E. 学術的な数値の語義

論文由来の数値は、**原論文の記述と語義まで照合**する。
例：「記録された種数」と「新種の数」は別物。「5,578種を記録し、うち約9割が未記載」を「5,000超の新種を発見」と書くと不正確になる。

### F. 情報源リンク（機械的確認）

- 各 `<a class="source-item">` の URL が実在するか（404でないか）
- `source-name` および `source-desc` の記述が、**実際のページ内容と一致**するか（媒体名と中身のズレがないか）

※ 一部サイトは自動取得を拒否（403）する。その場合は検索結果でページの実在とタイトルを確認し、「403のため本文未確認」と報告する。

### G. 調査メモとの突合（新規記事のみ可能な検査）

記事作成セッションに残っている調査時の検索結果と、最終原稿を突き合わせる。
**転記のズレ**（調査では「40カ国」だったが本文が「43カ国以上」等）を検出する。
あわせて、**その調査結果自体が最新か**を再確認する。調査時点で古い情報を掴んでいた可能性がある。

## 報告フォーマット

サブエージェントには以下の形式で報告させる。

```
## 🔴 重大な問題
- [箇所] 記事の記述 → 正しい事実 / 根拠（URL）

## 🟡 要修正
- [箇所] 記事の記述 → 正しい事実 / 根拠（URL）

## ✅ 裏付けが取れた主要記述
- 記述 … 確認できた根拠

## 判断が必要な項目
- 選択肢を伴う論点（図表の扱いなど）
```

**推測で「おそらく正しい」と report しない。** 確認できなかった項目は「未確認」と明示する。

## 過去の失敗事例（再発防止のため保持）

| 事例 | 内容 | 該当する検査項目 |
|---|---|---|
| チャートの数値を創作 | 「陸上埋蔵量を上回る」という定性記述から指数（130/300/500）を逆算して作成。推移グラフの過去5年分も創作 | C |
| モラトリアム国数の過大 | 「43カ国以上」と記載したが、最新の実名リストは40カ国 | A・G |
| 最新動向の欠落 | 記事公開日にISA会合が開催中だったが、時系列が4か月前で終わっていた | D |
| 学術数値の語義ズレ | 「5,578種を記録・約9割が未記載」を「5,000超の新種」と表現 | E |
| 最上級の誤り | 「史上唯一の独立クルド国家」（先行する短命な政体が存在） | B |
| 条約内容の不正確 | 「セーヴル条約で独立を約束」（実際は自治と条件付き独立の可能性を規定、条約は未発効） | A |
| 主観的強弱の偽装数値化 | perspective-cardの `tone-meter` で「推進度92%」のように、出典のない感覚的な評価を精密な百分率として提示 | C |
