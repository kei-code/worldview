# WorldView 日本語の自然さチェック・スキル

記事を**公開（コミット）する前に通す**検証工程。`/fact-check`（事実の正誤）とは独立した、**文章そのものの自然さ**を見る工程。

対象は**これから公開する新規記事**。

---

## なぜこの工程が要るか

過去に、公開済み記事で次の誤りが見逃された。

> 45か国 — 一社の製品が、**世界地図に広がっていた**
> だが2025年以降、**リズムの後半がほどけ始めている**

どちらも「地図が広がる場所になる」「リズムが結び目のようにほどける」という、**語と語の結びつきが日本語として成立していない**誤り。文法は正しく、単語も普通なので、読み流すと気づきにくい。

`lint.py`（同梱の形態素解析ツール）は常套句・構文の反復は数えられるが、この種の**意味的な結合の破綻**は判定できない。`/fact-check` も対象外（事実ではなく言い回しの問題のため）。したがって専用の工程を置く。

---

## 中核となる原則

### 1. 書いた本人には、自分の比喩が不自然に見えない

書き手にとって自分の比喩は「意図してそう書いた」ものなので、実在の言い回しかを問い直す動機が働かない。したがって**判定は必ずサブエージェント（Sonnet）に委譲する**。サブエージェントは記事HTMLしか読めず書き手の意図を知らないため、「この日本語は成立しているか」だけを見ざるを得ない。

### 2. 一番確実な予防は、そもそも凝った比喩を書かないこと

判定に頼る前に、**執筆の時点で比喩を避ける**。詳細は次節。

---

## 執筆時の文体方針（予防・最重要）

**凝った比喩を使わない。事実と論理をそのまま書く。**

不自然さの根本原因は、印象を強めようとして語を組み合わせにいくことにある。書いた比喩が実在の言い回しかを都度チェックするより、**比喩に頼らず書く**ほうが確実で、結果として読みやすくもなる。

| 避ける（装飾） | 書き直し（事実） |
|---|---|
| 一社の製品が、世界地図に広がっていた | 一社の製品が、45か国で使われていた |
| リズムの後半がほどけ始めている | 制裁を科す側の動きが鈍り始めている |
| 規制は水面を叩いているに近い | 規制は買い手に届いていない |

執筆時に守ること：

- 比喩を使わずに書けるなら、使わない
- 一文は50〜60字を目安に切る（文化庁「公用文作成の考え方」）
- 主語と述語を近づける。修飾語を重ねない
- 「〜という事実である」「〜に他ならない」のような大げさな締めを多用しない

**例外**：記事タイトルとセクション見出しは、端的で印象に残る言い方をしてよい（例：「500ドルの空軍」「火の輪は、なぜ消えたか」）。これは見出し語としての機能であり、本文の地の文とは別。**本文は説明を優先する。**

---

## 実行手順

### 1. 本文を抽出する

`lint.py` はMarkdown/プレーンテキスト前提のため、記事HTMLから地の文だけを抜き出す前処理が要る。専用スクリプトを使う：

```bash
cd .claude/skills/natural-japanese/scripts
uv run extract_article_text.py <記事のindex.html> -o ../check-target.txt
```

情報源セクション（06）・タグ・日付などのラベルは自動で除外される（`--keep-sources` で含めることも可）。

### 2. 機械検査（lint.py）を通す

```bash
cd .claude/skills/natural-japanese/scripts
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8   # Windows既定のcp932だと文字化けする
uv run lint.py ../check-target.txt --genre essay
```

検出される主なカテゴリ：
- `forbidden_phrase`：`references/forbidden-patterns.md` にある常套句・LLM臭い表現
- `antithesis_repetition`：「〜ではなく、〜」の多用（文書全体で3回以上）
- `repeated_sentence_lead`：同じ書き出しの反復（タイムラインの日付やラベル起因の誤検出もあるので、`情報`と`警告`の区別と対応箇所を見て判断する）
- `low_lexical_diversity_ttr`：語彙の使い回し

**この結果はそのままユーザーに出さず、次の意味検査とあわせて一つの報告にまとめる。**

### 2.5 事前チェック（サブエージェント起動前に必ず実施）

サブエージェントに投げる前に、抽出したテキストで以下2つの言い回しの**型**が残っていないか自分で軽く見る（過去の実例そのものの再発防止）：

- 「〜が、地図・世界に広がっていた／広がる」のような、**表現物（地図・図表・画面）が場所であるかのように扱う言い方**
- 「リズム・空気・雰囲気が、ほどける／溶ける／崩れる」のような、**抽象名詞に物理的な変化動詞をそのまま付ける言い方**

見つかった場合は、意味検査を待たずにこの場で直す。

### 3. 意味検査をサブエージェントに委譲する

`Agent` ツール（`subagent_type: "general-purpose"`, `model: "sonnet"`）で起動する。プロンプトには**抽出済みテキストの絶対パスと、下記「検査項目」の全文**を含めること。サブエージェントは会話の文脈を引き継がないため、指示は自己完結させる。

Read を使わせる（Web調査は不要）。

### 4. 報告を受けて修正方針を決める

サブエージェントの報告と、手順2の`lint.py`結果をあわせて、**重大度で仕分けしてユーザーに提示**する。

- 🔴 **日本語として成立していない**：語の結びつきが破綻している。必ず直す
- 🟡 **装飾過多**：比喩自体は成立するが、事実の記述で置き換えたほうが読みやすい。判断はユーザーと相談
- ✅ **確認したが問題なかった箇所**

修正は本体エージェントが行う。サブエージェントの役割は検出と報告まで。

### 5. 修正して再検査

修正箇所について、手順1〜2を再実行し、新規の不自然さを生んでいないか確認する。

### 6. 修正前後を事例集に追記する（必須）

このチェックで見つかった不自然な日本語（🔴・🟡・文言どうしの矛盾など）を直したら、**修正前後を `notes/natural-japanese-case-studies.md` に追記する**。記事ごとに1節を追加する累積型のファイルで、検査プロンプトやスキルの改善に使う実例集になっている。

- **いつ**：修正が終わった時点（ユーザーが追加で指摘した分は、直したあとに同じ節へ追記する）
- **書くもの**（直近の節 `## 10. sweden-election` を手本にする）：
  - 記事のパスとタイトル、この記事に固有の条件（材料・字数制約・読者層など）
  - 検出ごとの表：**検出（重大度・該当箇所）／問題点／修正後**。原文は省略せず、修正後の文もそのまま書く
  - lint.py の検出件数と、許容した理由（固有名詞由来の文頭反復など）
  - 型の分析（コロケーション破綻、直訳、レジスター、説明不足、見出しのずれなど。既出の型との関係も書く）
- **ファイル内の更新箇所**：冒頭の対象記事一覧と「方法」、末尾の「lint検出件数比較」表、「傾向まとめ」の通し番号（新しい示唆がある場合のみ）
- 修正案をユーザーが選んだ場合や、本体が調整した場合（サブエージェントの代案を変えたなど）は、その旨を書く
- 見出し・本文の修正で、ユーザーが後から再指摘した場合も、その経過をそのまま残す

## 検査項目（サブエージェントに渡す全文）

```
以下はWorldView（地政学ニュースサイト）の記事本文（プレーンテキスト抽出済み）です。
日本語として不自然な箇所を検出してください。事実の正誤は対象外です。

【最優先で探すもの：コロケーション破綻】
「語と語の組み合わせが日本語として成立していない」表現を探す。
過去の実例：
- 「一社の製品が、世界地図に広がっていた」→ 地図は物が広がる場所ではない
- 「リズムの後半がほどけ始めている」→ ほどけるのは結び目・糸であり、リズムには結びつかない

判定手順：
1. 本文中の比喩・装飾的な言い回しをすべて抜き出す
2. 各々について問う：「これは事実の記述に置き換えられないか」
   - 置き換えられる → 🟡装飾過多として報告し、書き直し案を出す
   - 比喩でしか表現しにくい → 3へ
3. 「主語＋述語」だけに縮約する（例：「製品が地図に広がる」）
4. 縮約した組み合わせが、実際の日本語（新聞・書籍）で使われる言い方かを判定する。
   頭の中で情景を描いたとき、破綻していないか確認する
5. 成立しないものは🔴として報告し、なぜ不自然かの説明と自然な代案を出す

注意：タイトルやセクション見出し（短い名詞句・体言止め）は、意図的な強調表現として
許容範囲が広い。地の文（段落・文の中）に対して厳しく見ること。

【次に探すもの：翻訳調・過剰な締め】
- 無生物主語＋他動詞が不自然に続く箇所（例：「規制が現実を突きつける」のような直訳調）
- 「〜という事実である」「〜に他ならない」「〜と言えるだろう」のような、断定を大げさに
  演出する結び方が繰り返されていないか

【報告フォーマット】
## 🔴 日本語として成立していない（要修正）
- [該当テキストの冒頭15字程度] 原文 → 縮約形 → なぜ不自然か → 代案

## 🟡 装飾過多（事実の記述に置き換えられる）
- [該当テキストの冒頭15字程度] 原文 → 書き直し案

## ✅ 確認したが問題なかった箇所（比喩として成立している例を2〜3件）
- 表現 … 成立する理由

推測で「たぶん自然」と報告しないこと。判断に迷う場合は🟡として理由とともに報告する。
```
